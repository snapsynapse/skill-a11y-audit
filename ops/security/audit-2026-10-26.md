## Code Pattern Analysis

### SEC-001: Audit provider failures produce a successful security gate

Severity: medium. Category: OWASP A08:2021, also A06. Evidence: [scripts/audit-deps.mjs:27-37](../../scripts/audit-deps.mjs#L27).

`runAudit()` accepts any nonempty JSON stdout and ignores the command status. `collectAdvisories()` treats a missing `vulnerabilities` field as an empty collection. A structured npm error such as ENOAUDIT or ECONNRESET therefore prints a clean result and exits 0. This can conceal unavailable coverage during registry outages or configuration errors; it does not prove that today's direct scans failed.

Mock-only reproductions for both errors returned exit 0, while a clean-report control also returned 0. See [the reproduction](evidence/2026-10-26/audit-gate-repro.mjs) and [observed output](evidence/2026-10-26/audit-gate-repro.txt). Reject `report.error`, validate report shape and schema, distinguish command failure from a valid advisory report, and add regression cases for unavailable and malformed responses.

### SEC-002: Untrusted sitemap targets exceed the declared origin boundary

Severity: medium. Category: OWASP A10:2021. Evidence: [discover.js:550-575](../../a11y-audit/scripts/discover.js#L550), [scan.js:69-82](../../a11y-audit/scripts/scan.js#L69), [scan.js:139-154](../../a11y-audit/scripts/scan.js#L139), [scan.js:664](../../a11y-audit/scripts/scan.js#L664).

Discovery restricts sitemap document fetches by default, but preserves cross-origin leaf targets. Its plan still declares `originPolicy: same-origin`; the adapter/Action automatically feeds `scanList` to the scanner. A public sitemap containing a loopback admin URL produced a plan with that URL, no blocked fetches, and the same-origin policy label. The direct scanner sitemap path also follows arbitrary child sitemap URLs and default fetch redirects.

This behavior is deliberate and covered by an existing preservation test, but becomes a security boundary issue when untrusted sitemap data drives automatic scanning on a host with internal-network access. It is not an authenticated-data theft demonstration, and ordinary hostile-page subresources also require external network isolation. The authenticated path's strict target checks provide a separate boundary.

See [the mock-only reproduction](evidence/2026-10-26/ssrf-repro.cjs) and [its output](evidence/2026-10-26/ssrf-repro.json). Define approved origins for sitemap documents, leaf targets, and navigation redirects; require deliberate cross-origin opt-in; report excluded targets. Retain legitimate preview-host rewriting through an explicit mapping. Do not describe request interception alone as a complete network sandbox.

### SEC-003: Every scan disables Chromium sandboxing

Severity: medium. Category: OWASP A05:2021, also A04. Evidence: [scan.js:653-655](../../a11y-audit/scripts/scan.js#L653).

The scanner unconditionally launches Chromium with `args: ['--no-sandbox']`, including remote scans on ordinary developer machines. This removes an available containment layer. Host compromise would additionally require an applicable browser vulnerability; no renderer exploit or host compromise was demonstrated.

Preserve sandboxing by default. If a particular runner requires a compatibility override, make it explicit and document the external isolation required for that runner.

### SEC-004: Temporary Action server listens on all interfaces

Severity: medium. Category: OWASP A05:2021. Evidence: [action.yml:177](../../.github/actions/scan/action.yml#L177), installed http-server 14.1.1 `bin/http-server:69`.

The Action starts http-server without an address flag. The package defaults to `0.0.0.0`, while readiness and intended scan consumers use localhost. On a reachable self-hosted runner, other hosts can retrieve the selected `serve-path` tree during the scan. Impact depends on firewall exposure and the contents of the served directory.

Bind the temporary server to `127.0.0.1`. Review directory listing and dotfile behavior for the selected public build directory. A cloud runner's short lifetime is not proof that all consumers have network isolation.

### SEC-005: Direct sitemap loading has no application-level byte or deadline budget

Severity: low. Category: OWASP A04:2021. Evidence: [scan.js:139-143](../../a11y-audit/scripts/scan.js#L139).

The direct loader calls bare `fetch()` and buffers the complete body through `response.text()`. Its 50-document recursion cap does not limit response bytes, total target URLs, or total wall-clock work. A compromised sitemap can consume memory or prolong a CI job. Discovery's separate helper has a byte cap and timeout, so its protections do not cover direct scanner loading.

Use an abort deadline, bounded streamed response reads, redirect limits, and a total target/work budget. This is a local job availability risk; no service-wide denial-of-service was demonstrated.

### SEC-006: Passing checks and PR review are not enforced on main

Severity: low. Category: OWASP A08:2021. Evidence: live GitHub main ruleset `20615522`, inspected 2026-10-26.

The ruleset enforces history integrity but contains only `deletion` and `non_fast_forward` rules. It does not require a PR, review, or successful status checks. A writer can therefore bypass the repository's otherwise substantial validation suite. This is a governance hardening gap for authorized writers, not anonymous write access.

Decide which CI contexts and review policy should be required, then configure the ruleset with an explicit maintenance/bypass policy. This audit did not mutate repository settings.

## Methodology and Validation

Reviewed all bundled executable scripts, root tooling, Action/workflow definitions, both dependency graphs, authentication documentation and output schemas. The full code review was split across access/design, auth/config/integrity, and injection/logging/outbound/privacy reviewers, then findings were deduplicated against file/line evidence. No live attack payloads, internal-network requests, paid inference APIs, or cloud infrastructure scans were run.

Commands included direct `npm audit --json` for both graphs, repository audit gates, gitleaks history and complete tracked-tree scans, env/key tracking and ignore checks, pinned actionlint and zizmor commands, read-only GitHub alert/ruleset/settings queries, default and auditor zizmor personas, and one normal public HEAD request. Two mock-only security reproductions are retained alongside their outputs. To rerun either reproduction from the repository root, pass its path to Node; both default their source root to the current directory and make no live HTTP requests.

Local deterministic validation passed 30/30 checks and the CLI contract passed 17/17. [Hosted run 40441160702](https://github.com/snapsynapse/skill-a11y-audit/actions/runs/40441160702) passed all ten jobs at the source commit above: four Node validation lanes, three browser lanes, GuideCheck, Action consumer and workflow security. Browser lanes include authenticated fixture coverage, clean external consumer installation, skip-download cache reuse, stale package repair, baseline scans and CLI consumers.

The local npm install completed but npm 11 reported Puppeteer's lifecycle script was not approved by local install-script policy. Hosted clean-browser execution supplies the browser validation evidence; successful local package installation alone does not claim browser acquisition. Existing human verification dates and immutable publication records were preserved.

Limitations: static review and test fixtures are not penetration testing, compliance certification, a browser exploit assessment, a cloud configuration audit, or proof that hostile-page networking is contained. Findings are conditional on the documented CLI/runner trust boundaries. Dependency advisory results are a point-in-time provider response.
