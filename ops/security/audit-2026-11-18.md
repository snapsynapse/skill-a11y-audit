## Security code findings
### SEC-007: preview server serves files outside its root through symlinks
Severity medium, P2, OWASP A01/A05. [serve-local.js:20](../../a11y-audit/scripts/serve-local.js#L20) blocks lexical hidden path segments, then lets http-server follow filesystem symlinks. A visible link to a harmless file outside the served tree returned HTTP 200 and the sentinel contents. A visible alias can similarly bypass hidden-name protection. Loopback binding reduces reachability, but content running in the scanned local origin can request the alias.
Recommendation: reject symlink components/targets and special files, or use canonical containment plus resolved hidden-segment checks and race-resistant opens. Test outward file/directory symlinks, visible-to-hidden aliases, encoded aliases, broken links and a regular-file control in `test-action-consumer.mjs`. Evidence: [access-repro.txt](evidence/2026-11-18/access-repro.txt). This extends prior SEC-004; the lexical fix remains present, but its boundary is incomplete.
### SEC-008: authenticated artifact directories can contain raw input aliases
Severity medium, P2, OWASP A01/A09. [auth-state.js:26](../../a11y-audit/scripts/auth-state.js#L26) checks an output and its own inode, not directory descendants. An artifact directory containing a hardlink to the synthetic state file passed the guard. [Action:294](../../.github/actions/scan/action.yml#L294) collects discovery/selection paths even when those stages are unused, so an unused output configured as this directory can collect the raw state alias after the guard succeeds.
Recommendation: allow explicit regular artifact files only during authenticated scans and collect only outputs from enabled stages; validate again immediately before upload. If directories remain supported, inspect descendants by realpath and device/inode. Extend `test-auth-state.js` with nested hardlinks/symlinks, unused directory outputs and expected upload denial. Evidence: [integrity-results.json](evidence/2026-11-18/integrity-results.json). This requires a configured existing alias; no page-to-runner filesystem write was demonstrated and no artifact was uploaded.
### SEC-009: guide-pinned report action executes unpinned imported code
Severity medium, P2, OWASP A08. [report.js:14](../../a11y-audit/scripts/report.js#L14) requires scan.js before validating its bytes. The [generate-report action](../../assistant-guide.txt#L136) pins report.js only. An unchanged report file in a disposable bundle executed a harmless modified scan.js sentinel before processing input.
Recommendation: verify the executable dependency before require, or extract/pin a small pure evidence helper. Add deterministic mutation tests over every guide entry point's transitive local executable graph; failure must precede sentinel execution. Preserve release-guide anchoring rules when delivering a fix. Evidence: [integrity-repro.mjs](evidence/2026-11-18/integrity-repro.mjs). Local bundle tampering is required; this is not anonymous remote code execution.
### SEC-010: unresolved or cyclic audit references still produce a clean gate
Severity medium, P2, OWASP A08/A06. [audit-deps.mjs:46](../../scripts/audit-deps.mjs#L46) accepts arbitrary string `via` references; [line 61](../../scripts/audit-deps.mjs#L61) skips them when collecting advisories. A report claiming one high vulnerability with a missing reference, or a self-cycle, passes shape/count validation and exits 0 with a clean message. A genuine inline high advisory control exits 1.
Recommendation: require references to resolve through the vulnerability graph to concrete advisories, reject dangling/cyclic-only chains, reconcile severity buckets against entries and treat unexplained high/critical nodes as unavailable coverage. Add graph cases to `test-security.js`, retaining valid propagated dependency and moderate-only controls. Evidence: [audit-reference-results.json](evidence/2026-11-18/audit-reference-results.json). This is a residual incompleteness of prior SEC-001's malformed-report fix, not evidence that the real npm reports in this audit were malformed.
### SEC-011: site staging allows symlinks outside reviewed docs
Severity low, P3, OWASP A01/A05. [build-site.mjs:20](../../scripts/build-site.mjs#L20) checks lexical hidden paths but not link targets; [line 42](../../scripts/build-site.mjs#L42) copies symlinks. A temporary `docs/public.txt -> ../private.txt` fixture passed build and produced a readable staged alias to synthetic outside content. The pinned [Pages artifact action](https://raw.githubusercontent.com/actions/upload-pages-artifact/fc324d3547104276b827a68afc52ff2a11cc49c9/action.yml) dereferences links when archiving, turning the alias into artifact content.
Recommendation: reject source symlinks and special files, or enforce realpath containment for every staged file. Use deterministic isolated build fixtures for outward file/directory links, hidden targets, valid normal files and required hidden files. This is an accidental-publication boundary; no such link is asserted to exist in current tracked docs. Evidence: [integrity-results.json](evidence/2026-11-18/integrity-results.json).
### SEC-012: discovery work lacks aggregate budgets and document deduplication
Severity low, P3, OWASP A04. [discover.js:498](../../a11y-audit/scripts/discover.js#L498) independently fetches every child. Seven repeated locations produced seven requests. Per-resource byte/time limits do not bound total documents, bytes, targets or fingerprinting duration across the run.
Recommendation: share a normalized visited set and aggregate document/byte/target budgets, plus one absolute deadline across discovery, crawl and fingerprinting. Test duplicate fetch count, aggregate limits and injected-clock deadlines rather than slow wall-clock tests. Evidence: [discovery-repro.json](evidence/2026-11-18/discovery-repro.json). Prior SEC-005's direct scanner-loader budgets remain implemented; this is the separate discovery path.

## Mitigation order and deterministic coverage plan
1. Gate/readiness and evidence safety: fix RV-001, RV-003, RV-002 and RV-005. These affect whether a CI result is trustworthy and whether accepted input survives. Use end-to-end operational outcome tests and baseline/input digest assertions.
2. Authenticated artifacts and local serving: fix SEC-008 and SEC-007 before expanding authenticated consumer adoption. Use an alias matrix for direct/nested symlinks and hardlinks, ancestor directories and unused stage outputs; assert no serving/upload collection.
3. Executable/provider integrity: close SEC-009 and SEC-010 with guide dependency-graph mutation tests and npm advisory-reference graph cases. Reject missing/cyclic references rather than relying on aggregate totals alone.
4. XML, resource and parser behavior: address RV-004/RV-007 together at the contract level, then SEC-012/RV-006. Preserve one-pass semantics in each owning implementation and verify the target server's received URL.
5. Publication and dependency maintenance: close SEC-011 and DEP-004 with isolated build fixtures and a reviewed locked patch update. No deployment is required to test either local boundary.
Additional preventive scripts/evals:

- Managed-install identity: [scan.js:505](../../a11y-audit/scripts/scan.js#L505) checks only Puppeteer's top-level version. Record a digest of the successfully installed lock and verify the managed graph against it. Test a changed transitive lock with the same Puppeteer version, axe drift and interrupted installation. An audit of the lock does not prove an existing native installation uses it; Action's explicit npm ci is separate evidence.
- Baseline-first adoption proof: implement the existing unchanged/new/fixed plan using one unchanged accepted baseline digest. Capture actual native 0/2/0 outcomes and retained old findings. Hosted red/green claims still require separately authorized hosted runs.
- Bundle metadata maintenance: add a deterministic check/update helper for listed file hashes and changed-file inventory versions, with a check-only mode for CI and a mutation fixture. Do not derive acceptance or auto-refresh baselines. This would prevent a repeat of PR #36's stale hash failure.
- Release/site identity: compare staged executable/guide bytes and provenance against the selected release tag, not only ancestor relation and asset names. Test a descendant with the same package version and altered guide bytes. This is preventive; the reviewed candidate does not change guide bytes.
- Replace source-regex-only assertions with behavior/mutation tests wherever a claimed boundary can be exercised. Retain source/config assertions for literal pins and contract declarations. Use injected clocks/fetches for deterministic aggregate-budget checks; keep a small real-browser integration layer.
